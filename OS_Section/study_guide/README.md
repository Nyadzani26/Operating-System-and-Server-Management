## MEMORY MANAGEMENT

### Memory Hierarchy

Memory in a computer system is organized in a hierarchy based on speed and cost:

**Registers** (fastest, most expensive) → **Cache** → **Main Memory (RAM)** → **Secondary Storage (Disk)** (slowest, cheapest)

**Key Principle:** Generally, registers are faster than cache, and cache is faster than main memory (RAM).

### Memory Abstraction

**Memory abstraction** separates the logical view of memory (as seen by programs) from the physical reality of how data is stored. This allows programs to use simple, contiguous address spaces without worrying about physical memory layout.

### Swapping

**Swapping** is the process of copying a process from main memory to secondary storage (swap space/disk) and back according to requirement. This allows the OS to run more processes than can fit in physical memory simultaneously.

**Why Swapping Matters:**
- Enables multiprogramming beyond physical memory limits
- Processes not currently executing can be swapped out
- Swapped-in processes resume from where they left off

### Fragmentation

**Internal Fragmentation:** Wasted space **within** an allocated memory block. Occurs when allocated memory is slightly larger than requested memory.
- **Example:** Process needs 18KB, gets allocated a 20KB block → 2KB wasted inside the block

**External Fragmentation:** Wasted space **between** allocated memory blocks. Total free memory exists but is scattered in small, non-contiguous pieces.
- **Example:** Have 100KB free memory but split into 10KB chunks → Cannot allocate a 50KB process

## SEGMENTATION VS PAGING

### Segmentation

**Segmentation** divides the logical address space into variable-sized segments based on logical divisions (code segment, data segment, stack segment).

**Characteristics:**
- **Division:** Logical divisions (code, data, stack, heap)
- **Size:** Variable size (each segment can be different)
- **Calculation/Formula:** Physical Address = Base + Offset (if Offset < Length)
- **Fragmentation:** External fragmentation (gaps between variable-sized segments)

**Advantages:**
- Reflects logical program structure
- Easy to share code/data segments between processes
- Protection at segment level (read-only code segment)

**Disadvantages:**
- External fragmentation
- Complex memory management

### Paging

**Paging** divides logical address space into fixed-sized blocks called pages, and physical memory into frames of the same size.

**Characteristics:**
- **Division:** Fixed-sized blocks (pages in logical, frames in physical)
- **Size:** Fixed size (all pages/frames same size, typically 4KB)
- **Calculation/Formula:** Physical Address = (Frame Number × Page Size) + Offset
- **Fragmentation:** Only internal fragmentation (in last page of process)

**Advantages:**
- Eliminates external fragmentation
- Simple memory allocation (any frame can hold any page)
- Easy to implement

**Disadvantages:**
- Internal fragmentation in last page
- Page table overhead (memory needed to store mappings)

### Comparison Table

| Aspect | Segmentation | Paging |
|--------|--------------|--------|
| **Division** | Logical units (code, data, stack) | Fixed-size blocks |
| **Size** | Variable (different segment sizes) | Fixed (uniform page/frame size) |
| **Formula** | Base + Offset (check Offset < Length) | (Frame# × PageSize) + Offset |
| **Fragmentation** | External | Internal (last page only) |
| **User View** | Visible to programmer | Transparent to programmer |

## LOGICAL AND PHYSICAL ADDRESSING

### Logical Address (Virtual Address)

**Logical address** is the address generated by the CPU during program execution. It's the address as seen by the process—relative to the start of the program.

**Components:**
- **Page Number (p):** Identifies which page
- **Offset (d):** Location within the page

### Physical Address

**Physical address** is the actual address in physical RAM where data is stored. The Memory Management Unit (MMU) translates logical addresses to physical addresses.

**Components:**
- **Frame Number (f):** Identifies which frame in physical memory
- **Offset (d):** Same offset as in logical address (within frame/page)

### Address Translation

```
Logical Address = (Page Number, Offset)
                     ↓ (via Page Table)
Physical Address = (Frame Number, Offset)
```

The **Page Table** maps page numbers to frame numbers. Each process has its own page table.

### Relocation and Limit Registers

**Relocation Register:** Contains the starting physical address of a process. Added to logical addresses to get physical addresses.

**Limit Register:** Contains the size of the logical address space. Used to check if logical address is valid.

**Rule:** Each logical address must be **less than** the limit register value. If not, it's an addressing error (segmentation fault).

## PAGE REPLACEMENT ALGORITHMS

When a page fault occurs and all frames are occupied, the OS must select a victim page to replace. Different algorithms make this decision differently.

### FIFO (First In First Out)

**How it works:** Replace the oldest page in memory (the one that has been in memory longest).

**Implementation:** Maintain a queue of pages in order of arrival. Replace the page at the front of the queue.

**Example:**
```
Reference String: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2
Frames: 3

Step-by-step:
7 → [7, -, -] (Page fault)
0 → [7, 0, -] (Page fault)
1 → [7, 0, 1] (Page fault)
2 → [2, 0, 1] (Page fault, replace 7)
0 → [2, 0, 1] (Hit)
3 → [2, 3, 1] (Page fault, replace 0)
... continue
```

**Advantages:** Simple to implement

**Disadvantages:** Suffers from Belady's Anomaly (more frames can lead to more page faults); doesn't consider page usage

### LRU (Least Recently Used)

**How it works:** Replace the page that hasn't been used for the longest period of time.

**Logic:** Pages used recently are likely to be used again soon (temporal locality).

**Implementation:**
- **Counter Method:** Each page has a timestamp; replace page with oldest timestamp
- **Stack Method:** Maintain a stack of page numbers; most recently used is on top

**Example:**
```
Reference String: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2
Frames: 3

Track last use time for each page:
7 → [7, -, -] (Fault)
0 → [7, 0, -] (Fault)
1 → [7, 0, 1] (Fault)
2 → [2, 0, 1] (Fault, replace 7 - least recently used)
0 → [2, 0, 1] (Hit, update 0's timestamp)
3 → [2, 0, 3] (Fault, replace 1 - least recently used)
... continue
```

**Advantages:** Generally good performance; approximates OPT in practice

**Disadvantages:** Expensive to implement (need to track usage); requires hardware support

### LFU (Least Frequently Used)

**How it works:** Replace the page with the smallest reference count (used least number of times).

**Implementation:** Maintain a counter for each page; increment on access; replace page with lowest count.

**Problem:** A page used heavily in the past but not recently has high count and won't be replaced, even if no longer needed.

**Solution:** Can combine with aging (reduce counts over time) or use time-based windowing.

### OPT (Optimal) - Belady's Algorithm

**How it works:** Replace the page that won't be used for the longest period in the future.

**Characteristics:**
- Theoretically optimal (fewest page faults possible)
- Impossible to implement in practice (requires future knowledge)
- Used as benchmark to compare other algorithms

**Example:**
```
Reference String: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2
Frames: 3

Look ahead at future references:
When page fault occurs, replace the page that won't be needed for longest time
```

### Comparison

| Algorithm | Replaces | Advantages | Disadvantages |
|-----------|----------|------------|---------------|
| **FIFO** | Oldest page | Simple | Belady's Anomaly, ignores usage |
| **LRU** | Least recently used | Good performance | Implementation overhead |
| **LFU** | Least frequently used | Considers frequency | Old pages stay too long |
| **OPT** | Won't be used longest | Optimal | Impossible (needs future) |

## PROCESS MANAGEMENT

### What is a Process?

A **process** is a program in execution. It includes:
- Program code (text section)
- Current activity (program counter, register contents)
- Stack (temporary data: function parameters, return addresses, local variables)
- Data section (global variables)
- Heap (dynamically allocated memory)

### Process vs Program

**Program:** Passive entity (executable file on disk)  
**Process:** Active entity (program loaded into memory and executing)

One program can create multiple processes (e.g., multiple instances of a web browser).

### Process Creation

**fork() System Call:** Creates a new child process by duplicating the calling (parent) process.

**After fork():**
- Parent and child have separate memory spaces
- Child gets a copy of parent's data
- Both processes continue execution after fork()
- Parent receives child's PID; child receives 0

**Example:**
```c
pid = fork();
if (pid == 0) {
    // Child process code
} else {
    // Parent process code
}
```

### Process Termination

**Ways a process terminates:**
1. **Normal Exit:** Process completes execution and calls `exit()`
2. **Fatal Error:** Process encounters unrecoverable error (segmentation fault, divide by zero)
3. **Killed by another process:** Another process sends kill signal

**wait() System Call:** Parent process uses `wait()` to determine when child process terminates and retrieve exit status.

**Zombie Process:** Child process that has terminated but parent hasn't called `wait()` yet. Still occupies space in process table.

**Orphan Process:** Process whose parent has terminated. Orphaned processes are adopted by init (PID 1) or namespace init process, which reaps them.

### PID Namespaces

**PID Namespace:** Provides isolated process ID numbering. Processes in different namespaces can have the same PID.

**Key Rules:**
- First process in a namespace becomes init for that namespace (reaps orphans within namespace)
- When a process joins a namespace, orphaned children in that namespace are reaped by the namespace's init process
- Parent process outside the namespace still sees the child with its original PID

## CONTEXT SWITCHING

### What is Context Switching?

**Context switching** is the process of storing the state of a currently running process and loading the state of the next process to run. The stored state is called the **context**.

**Context includes:**
- Program counter
- CPU registers
- Process state
- Memory management information
- I/O status

### When Context Switches Occur

**Always results in context switch:**
1. **Blocking system call:** Process waits for I/O, another process must run
2. **Process termination (exit):** Dead process can't run, switch to another
3. **Timer interrupt (time slice expires):** Preemptive scheduling forces switch

**May result in context switch:**
4. **Disk interrupt servicing:** If blocked process becomes ready and has higher priority

**Does NOT always cause context switch:**
- Servicing interrupts alone (interrupt handling can complete and return to same process)

### Context Switch Overhead

Context switching takes time (saving/loading context) during which no useful work is done. Minimizing unnecessary context switches improves system performance.

## PROCESS STATES

### Basic Process States

**New:** Process is being created

**Ready/Runnable:** Process is waiting to be assigned to CPU (has everything it needs except CPU time)

**Running:** Process is currently using the CPU

**Waiting/Blocked:** Process is waiting for some event (I/O completion, signal)

**Terminated:** Process has finished execution

### State Transitions

```
New → Ready: Process created and admitted
Ready → Running: Scheduler dispatches process
Running → Ready: Time slice expires (preemption) OR higher-priority process arrives
Running → Waiting: Process blocks for I/O or event
Waiting → Ready: I/O or event completes
Running → Terminated: Process finishes or is killed
```

### Process States with Suspend

Modern systems add **suspended states** when processes are swapped to disk:

**Suspended Ready:** Ready process swapped out to disk

**Suspended Waiting:** Waiting process swapped out to disk

**Transitions:**
```
Ready → Suspended Ready: Swap out ready process
Suspended Ready → Ready: Swap in ready process
Waiting → Suspended Waiting: Swap out waiting process
Suspended Waiting → Suspended Ready: Event completes while swapped
Suspended Waiting → Waiting: Swap in waiting process
```

### Diagram: Process States (Two Suspended States)

```
         ┌──────────┐
         │   New    │
         └────┬─────┘
              ↓
         ┌────────────┐     timeout      ┌─────────────┐
    ┌───→│   Ready    │←─────────────────│   Running   │
    │    └──────┬─────┘                  └──────┬──────┘
    │           │          dispatch             │
    │           └────────────────────────────────┘
    │                                            │
    │                                            │ wait event
    │                                            ↓
    │                                      ┌──────────┐
    │               event occurs           │  Waiting │
    │           ┌──────────────────────────┤          │
    │           │                          └────┬─────┘
    │           │                               │
    │    swap in│                               │ swap out
    │           │                               ↓
    │    ┌──────┴────────┐             ┌────────────────┐
    └────│ Suspended     │             │   Suspended    │
         │ Ready         │←────────────│   Waiting      │
         └───────────────┘   event     └────────────────┘
                             occurs
```

## SCHEDULING POLICIES

### Preemptive vs Non-Preemptive

**Preemptive Scheduling:** OS can interrupt running process and switch to another (timer interrupts enable this).

**Non-Preemptive Scheduling:** Process runs until it voluntarily gives up CPU (blocks or terminates).

### Round-Robin Scheduling

**How it works:** Each process gets a small time slice (time quantum). When time expires, process is preempted and moves to end of ready queue.

**Example Policy (from test):**
- Each process runs for maximum 10 milliseconds
- Process may block or terminate before 10ms
- After 10ms or blocking, OS switches to next ready process in round-robin fashion

**Characteristics:**
- **Requires timer interrupts** (to enforce time quantum)
- **Preemptive** (processes can be involuntarily interrupted)
- **Fair** (all processes get equal CPU time)
- Does **NOT prioritize** short processes over long processes

**Involuntary Context Switch:** Occurs when time quantum expires and process is preempted.

## INTERRUPT HANDLING

### What is an Interrupt?

An **interrupt** is a signal that causes the CPU to stop its current activity and execute a special function (interrupt handler). Interrupts allow hardware to get CPU attention without polling.

### Types of Interrupts

**Hardware Interrupts (IRQs):** Generated by hardware devices (keyboard, disk, timer, network card).

**Software Interrupts:** Generated by software (system calls, exceptions like divide-by-zero).

### Interrupt Descriptor Table (IDT)

The **IDT** is a table of pointers stored in low memory, containing the address of the interrupt handler for each interrupt number.

**Structure:**
```
Interrupt # | Handler Address | CPU Register Values
     0      |    0x...       |  CS, EIP, etc.
     1      |    0x...       |  CS, EIP, etc.
     ...    |    ...         |  ...
     n      |    0x...       |  CS, EIP, etc.
```

**IDT Entry specifies:**
- Address of interrupt handler code
- Values to load into CPU registers before handling interrupt (e.g., CS - Code Segment, EIP - Instruction Pointer, SS - Stack Segment)

### Interrupt Handling Steps

1. **Hardware detects interrupt** and signals CPU
2. **CPU finishes current instruction** (atomic)
3. **CPU looks up handler address** in IDT using interrupt number
4. **CPU saves current context** (push registers, program counter to stack)
5. **CPU loads new context** from IDT entry (CS, EIP, etc.)
6. **Interrupt handler executes** (device-specific code)
7. **Handler sends EOI** (End Of Interrupt) signal to interrupt controller
8. **CPU restores saved context** and resumes interrupted process

### IRQs (Interrupt Request Lines)

**Limited IRQs Problem:** Traditional systems have limited IRQ lines (often 16). With many devices, IRQs must be shared, which can cause conflicts and performance issues.

**IRQ Sharing:** Multiple devices use the same IRQ line. OS must poll each device on that IRQ to determine which triggered the interrupt.

### APIC (Advanced Programmable Interrupt Controller)

**LAPIC (Local APIC):** Each CPU core has its own LAPIC for receiving interrupts and inter-processor interrupts (IPIs).

**I/O APIC:** Centralized interrupt controller that routes interrupts from I/O devices to appropriate LAPIC.

**Advantages:**
- More IRQ lines (up to 256)
- Better interrupt distribution in multi-processor systems
- Reduced IRQ sharing conflicts
- Support for Message Signaled Interrupts (MSI)

## VIRTUALIZATION

### What is Virtualization?

**Virtualization** allows multiple operating systems (guests) to run simultaneously on a single physical machine (host) by abstracting hardware resources.

**Virtual Machine (VM):** Software emulation of a physical computer, complete with virtual CPU, memory, disk, and network interfaces.

### Type 1 Hypervisor (Bare Metal)

**Architecture:** Hypervisor runs directly on physical hardware; guest OSs run on top of hypervisor.

```
┌─────────────┬─────────────┬─────────────┐
│   Guest OS  │   Guest OS  │   Guest OS  │
├─────────────┴─────────────┴─────────────┤
│           Hypervisor (Type 1)           │
├─────────────────────────────────────────┤
│          Physical Hardware              │
└─────────────────────────────────────────┘
```

**Examples:** VMware ESXi, Microsoft Hyper-V, Citrix XenServer, KVM

**Characteristics:**
- Direct hardware access
- No host OS overhead
- Better performance
- Lower latency
- More secure (smaller attack surface)

**Use Cases:**
- Data center servers
- Enterprise virtualization
- Cloud infrastructure (AWS, Azure)
- Production environments requiring high performance

**Configuration/Security:**
- Encryption at hypervisor level
- Hardware-assisted virtualization (Intel VT-x, AMD-V)
- Direct device assignment possible
- Dedicated management interface

### Type 2 Hypervisor (Hosted)

**Architecture:** Hypervisor runs as an application on a host OS; guest OSs run on top of hypervisor.

```
┌─────────────┬─────────────┬─────────────┐
│   Guest OS  │   Guest OS  │   Guest OS  │
├─────────────┴─────────────┴─────────────┤
│           Hypervisor (Type 2)           │
├─────────────────────────────────────────┤
│              Host OS                    │
├─────────────────────────────────────────┤
│          Physical Hardware              │
└─────────────────────────────────────────┘
```

**Examples:** VMware Workstation, Oracle VirtualBox, Parallels Desktop

**Characteristics:**
- Runs on existing OS
- Easier to install/setup
- Lower performance (host OS overhead)
- Higher latency (extra abstraction layer)
- More propagation delays

**Use Cases:**
- Desktop virtualization
- Development/testing environments
- Learning and experimentation
- Running multiple OSs on workstation

**Configuration/Security:**
- Depends on host OS security
- Encryption at application level
- Easier for users to manage
- Can use host OS features

### Comparison

| Aspect | Type 1 (Bare Metal) | Type 2 (Hosted) |
|--------|---------------------|-----------------|
| **Runs On** | Directly on hardware | On top of host OS |
| **Performance** | Excellent (native speed) | Good (some overhead) |
| **Latency** | Low | Higher |
| **Security** | More secure | Depends on host OS |
| **Use Case** | Servers, production | Desktop, development |
| **Examples** | Hyper-V, ESXi | VirtualBox, VMware Workstation |
| **Management** | Dedicated tools | Host OS tools |

## INTERPROCESS COMMUNICATION

### What is IPC?

**Interprocess Communication (IPC)** allows processes to exchange data and coordinate their activities.

**Types of IPC:**
- **Shared Memory**
- **Message Passing**
- **Pipes**
- **Sockets**
- **Signals**

### Shared Memory

**Shared Memory** is a memory region accessible by multiple processes—the fastest IPC mechanism because it avoids kernel mediation after setup.

**How it works:**
1. One process creates a shared memory segment
2. Other processes attach to the segment
3. Processes read/write directly to shared memory
4. Processes must synchronize access (semaphores, mutexes)

**Advantages:**
- **Fastest IPC method** (no copying, no kernel calls after setup)
- Efficient for large data transfers
- Low overhead

**Disadvantages:**
- Requires synchronization (race conditions possible)
- More complex programming
- Limited to single machine

**Use Cases:** High-performance applications, database systems, multimedia applications

## KEY FORMULAS & CALCULATIONS

### Logical Address Calculation

**Formula:**
```
Logical Address Bits = log₂(Total Logical Address Space)
                     = log₂(Number of Pages × Page Size)

Page Number Bits = log₂(Number of Pages)
Offset Bits = log₂(Page Size)

Total Logical Address Bits = Page Number Bits + Offset Bits
```

**Example:**
```
Logical address space: 64 pages of 1024 words each

Page Size = 1024 words = 2^10 words
Number of Pages = 64 = 2^6 pages

Offset Bits = log₂(1024) = 10 bits
Page Number Bits = log₂(64) = 6 bits
Total Logical Address Bits = 6 + 10 = 16 bits
```

### Physical Address Calculation

**Formula:**
```
Physical Address Bits = log₂(Total Physical Memory)
                      = log₂(Number of Frames × Frame Size)

Frame Number Bits = log₂(Number of Frames)
Offset Bits = log₂(Frame Size)  [Same as page offset]

Total Physical Address Bits = Frame Number Bits + Offset Bits
```

**Example:**
```
Physical memory: 32 frames of 1024 words each

Frame Size = 1024 words = 2^10 words (same as page size)
Number of Frames = 32 = 2^5 frames

Offset Bits = log₂(1024) = 10 bits
Frame Number Bits = log₂(32) = 5 bits
Total Physical Address Bits = 5 + 10 = 15 bits
```

### Segment Addressing

**Formula:**
```
Physical Address = Base + Offset

Valid if: Offset < Length (Limit)
```

**Example:**
```
Segment Table:
Segment | Base | Length
   0    | 219  |  600
   1    | 2300 |   14
   2    |  90  |  100

Logical Address (0, 430):
- Segment 0, Offset 430
- Check: 430 < 600? YES ✓
- Physical Address = 219 + 430 = 649

Logical Address (2, 500):
- Segment 2, Offset 500
- Check: 500 < 100? NO ✗
- INVALID ADDRESS (Segmentation Fault)
```

### Page Table Size Calculation

**Formula:**
```
Page Table Size = Number of Pages × Entry Size

Number of Pages = Logical Address Space / Page Size

Entry Size = Size needed to store frame number + control bits
```

**Example:**
```
Virtual address: 22-bit page number, 12-bit offset
Page table entries: 4 bytes each

Page Size = 2^12 bytes = 4 KB
Number of Pages = 2^22 pages
Page Table Size = 2^22 × 4 bytes = 2^24 bytes = 16 MB
```

### Memory Calculations Summary

| What to Find | Formula |
|--------------|---------|
| Logical Address Bits | log₂(pages × page_size) |
| Physical Address Bits | log₂(frames × frame_size) |
| Page Number Bits | log₂(number_of_pages) |
| Frame Number Bits | log₂(number_of_frames) |
| Offset Bits | log₂(page_size) = log₂(frame_size) |
| Page Size | 2^(offset_bits) |
| Page Table Size | number_of_pages × entry_size |
| Segment Physical Address | base + offset (if offset < length) |

## ADDITIONAL KEY CONCEPTS

### System Calls

**System call** is the interface between a process and the operating system. Processes use system calls to request OS services (file operations, process creation, communication).

**Common System Calls:**
- **fork():** Create new process
- **exec():** Load new program into process
- **wait():** Wait for child process termination
- **exit():** Terminate process
- **open(), read(), write(), close():** File operations

### Threads

**Thread** is a lightweight process—the basic unit of CPU utilization. Multiple threads within the same process share:
- Code section
- Data section
- Open files and other resources

But each thread has its own:
- Thread ID
- Program counter
- Register set
- Stack

**Advantages:**
- Faster creation/termination than processes
- Faster context switching
- Efficient communication (shared memory)

### Deadlock

**Deadlock** occurs when a set of processes are blocked, each waiting for a resource held by another process in the set. All processes remain blocked forever.

**Necessary Conditions (all four must hold):**
1. **Mutual Exclusion:** Resources cannot be shared
2. **Hold and Wait:** Process holds resources while waiting for others
3. **No Preemption:** Resources cannot be forcibly taken
4. **Circular Wait:** Circular chain of processes waiting for resources

### Policy vs Mechanism

**Mechanism:** The low-level implementation—*how* something is done.  
**Policy:** The high-level decision—*what* should be done.

**Separation of Policy and Mechanism:** Keep policy decisions separate from mechanism implementation for flexibility.

**Example:**
- **Mechanism:** How to switch between processes (context switching code)
- **Policy:** Which process to run next (scheduling algorithm)

**Benefits of Separation:**
- Can change policy without changing mechanism
- Different policies can use same mechanism
- Easier to adapt system to different environments
